## 1. Scope — what 1.6.0 adds

A performance-intelligence line layered on the existing audit skill. Every addition is opt-in and
read-only; no existing ID, CLI flag, JSON contract or baseline changed.

- **Increment 1 — `perf-audit.mjs`:** static performance patterns (render-blocking shapes,
  unguarded `Date.now()`/`Math.random()` and browser APIs in server render, resources without
  cleanup already covered, heavy imports on the initial path), each finding classed
  confirmed/heuristic/info with `path:line`.
- **Increment 2 — `browser-audit --vitals`:** opt-in lab Core Web Vitals in Chromium (LCP, CLS and
  the Navigation-Timing proxies), labelled as lab under a named profile, never field data.
- **Increment 2B — the Strict Mode lesson:** the R3F lab ties its GPU resources to the mount, not a
  memo, so React Strict Mode's double-invoke keeps its context; documented in the performance
  reference as an ownership rule.
- **Increment 3 — `browser-audit --interactions` and `--hydration-cost`:** interaction latency from
  the Event Timing API (input delay / processing / presentation grouped by `interactionId`, LoAF
  attribution of the slow handler) and hydration cost from Navigation-Timing proxies, boot long
  tasks, JS transfer and the app's own `performance.mark`. The Playwright wall-clock is kept only as
  a labelled proxy; neither is ever reported as field INP or an exact hydration time without a
  marker.
- **Increment 4 — `route-attribution.mjs`:** per-route JS/CSS attribution (initial vs deferred,
  shared counted once) and rendering strategy (SSG/ISR/SSR) read from the real build manifests
  (Next's per-route client-reference and prerender manifests, Nuxt's client/precomputed manifests),
  correlated with `perf-audit`. It reuses `lib/bundle.mjs` (extracted from `bundle-budget`); it does
  not add a second dependency engine or budget system. It never equates built, route-associated,
  browser-requested, transferred and used bytes, and names its uncertainty.
- **Increment 5 — `perf-budget.mjs`:** a pure evaluator over the JSON the other tools already emit.
  Five typed states (PASS, FAIL, UNAVAILABLE, INSUFFICIENT_DATA, INVALID_CONFIGURATION); a
  before/after comparison that blocks incompatible pairs (different profiles or units) rather than
  reading them as a change. No second auditor, engine or budget system.

## 2. New surface and contracts

- **Three new scripts** (total twelve → **fifteen**): `perf-audit.mjs`, `route-attribution.mjs`,
  `perf-budget.mjs`. All documented in `scripts/README.md` and `SKILL.md`, all executable.
- **One shared library extracted:** `lib/bundle.mjs` (manifest readers), reused by `bundle-budget`
  and `route-attribution` so there is a single build-evidence reader.
- **The perf-budget contract:** categories build/route/network/experience/diagnostic; the five
  states above; a before/after compatibility gate; `profileLabel() = viewport|cpu|net|cache`. It
  never equates magnitudes across units or profiles.
- **The end-to-end flow** (opt-in, no new orchestrator): `perf-audit → route-attribution →
  bundle-budget → browser-audit → perf-budget`, documented in `scripts/README.md` and
  `references/performance.md`.

## 3. Critical-metric audit (Fase 3) and its one fix

The author's critical-metric self-review of the comparison logic (not an independent review; see §9
for the independent audit) found one **Important** defect and judged the rest acceptable or
documented:

- **Fixed:** the before/after verdict used the p75 **point** against a fixed ±2 % band and ignored
  the per-run spread, so it could claim an effect that was inside run-to-run variance. The verdict
  is now **data-driven and overlap-aware**: when the per-run ranges overlap the verdict is
  `inconclusive` (the change is within variance at the stated sample counts); a win or regression is
  only claimed when the ranges separate, with the ranges printed in the note. Two regression tests
  (fixture L: overlapping vs separated) lock the behaviour. Commit `8995746`.
- **Confirmed acceptable:** missing data stays UNAVAILABLE/INSUFFICIENT_DATA (never a false PASS or a
  zero); different profiles/units are INVALID_CONFIGURATION (never an improvement); lab labels name
  the profile; the heuristics are triaged and named; the profiler remains a pointer for causality,
  not a cause.
