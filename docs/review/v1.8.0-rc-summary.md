# Frontend Architect v1.8.0 — release-candidate summary

One page for the 1.8.0 release decision. **1.8.0 is an agent-ready design-system line plus the evaluation-harness
fixes the first real behavioural runs forced.** It adds the sixteenth script, a doctrine reference and a copyable
Nuxt layer; it changes no existing audit rule, id, level, JSON shape, exit code or frozen baseline. Behavioural
evaluations are **exploratory** (one case on two models, eight cases once on Haiku); no claim that the skill
measured-better than 1.7.0 is made anywhere.

## 3. What is NOT claimed

- That Frontend Architect makes Claude Code measurably better (one run per arm is exploratory; Δ = 0 on the cases reading
  alone can answer; activation is model-dependent and the bottleneck).
- That the inventory is semantic: v1 is lexical by design, says so in its `Analysis` line, and lists its known limits.
- That 100 % on the dev corpus is generalization: the blind hold-out's first measurement (80 % recall) is the honest number
  for the tool as first written; the post-fix 100 % is reported as post-fix.
- That the starter is a component library: it is nine components and the properties, to be copied and replaced.
- That the skill descriptions were improved: the wording is proposed and awaits a before/after on Sonnet.

## 4. Residual risks

- Activation (1b): unmeasured after the proposal; the before/after needs ≈ 4 USD of Sonnet runs and an authorization.
- The inventory's heuristic data-view recogniser can call a static list a data view when a `loading`/`state` prop is
  near (documented, heuristic level).
- `plugins/frontend-architect/evals/results/` holds the local pilot traces (gitignored); they are the evidence behind
  the pilot numbers and exist only on this machine.
- The starter pins Nuxt UI `^4.12` semantics (`dismissible`, `close:prevent`); a Nuxt UI major would need a re-check.
