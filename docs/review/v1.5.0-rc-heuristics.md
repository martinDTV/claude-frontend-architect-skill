# v1.5.0 release candidate: triage of the standing heuristics (increment 6, 2026-10-31)

Source: `browser-audit` run by `verification/browser/review-captures.mjs` over the twelve routes of the three reference products (Atlas in Nuxt UI and in shadcn/ui, Lumen, Ember) at mobile 375, desktop 1280 and reflow 320 px, with 100% and 200% text, before any fix of this increment (`audit-nuxt.json`: 0 confirmed, 25 heuristic, 5 info; `audit-next.json`: 0 confirmed, 10 heuristic, 3 info; both under `verification/browser/evidence/review-rc/`, regenerable with the script). Every heuristic is listed with its evidence and filed as a **confirmed defect**, a **false positive**, a **legitimate exception**, a **detector limitation** or **not verifiable**. Rule severities were not changed to make anything disappear: the two detector corrections below narrow what the rule counts, each with a fixture page that keeps the rule's positive case.

Reproduction for every row: build the app (`npx nuxt build` in `verification/nuxt`, `npx next build` in `verification/next`), serve it, and run `node scripts/browser-audit.mjs <url> --playwright verification/browser --paths <route> --checks axe,keyboard,responsive --viewports mobile,desktop,reflow --text-scale 1,2 --json`; or run `node verification/browser/review-captures.mjs`, which does all of it and writes the JSON next to the screenshots.
