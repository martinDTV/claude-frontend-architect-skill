# Frontend Architect v1.7.0 — Release-candidate documentation

One page for the v1.7.0 release decision. v1.7.0 is an **evaluation-infrastructure and measurement line**,
not a new-capability line: it adds the machinery to measure how well the auditors and the skill behave,
and fixes one measurement defect in the browser auditor. It does **not** add or change any production
audit rule, and it does **not** bump the published version. HEAD at writing is a local branch 15 commits
ahead of the published 1.6.0 (`9183066`); nothing is pushed, tagged or released.

> **This candidate is NOT certified by behavioural evaluation.** Every eval that needs a model to run
> (E0B/E1) is **NOT_RUN**. v1.7.0's evidence is structural and offline. See §4.

## 3. Residual risks

- **No behavioural measurement yet.** The skill's end-to-end behaviour (does Claude Code use the right
  auditor, find the planted defect, abstain correctly) is **unmeasured** — the pilot is NOT_RUN (§4).
- **The corpus numbers are in-sample.** 96.4%/94.6% are a development-set characterization, not a
  general-performance claim; the hold-out bounds but does not eliminate unknown FP/FN (21 cases is a
  check, not a census). Known structural limits (variable resolution, cross-file auth/validation,
  import-kind coverage, custom ARIA widgets, transferred bytes) are documented, not fixed.
- **The pilot's Bash grant (`Bash(node:*)` plus a read-only allowlist since the first real run) is least-privilege, NOT an OS sandbox.** The CLI runs scaffolds
  and tools as the operator outside the OS sandbox, and `node` can still touch the filesystem; the real
  containment is the throwaway scaffold cwd and read-only prompts.
- **The harness aggregate-budget guard is the script's own check, not a guaranteed billing cap.** Cloud
  budget alerts are notifications, not hard caps; real spend must be watched.
- **GPU/WebGL flaky** in the 3D lab checks: an environmental Chromium-on-macOS process crash, seen once,
  not reproduced since; documented, not fixed (out of scope).

## 4. E0B/E1 status — explicitly NOT_RUN

No model has been run for v1.7.0. All behavioural (E0B) and model-judge (E1) results are **NOT_RUN**: the
eight-case pilot, the version comparison, the implementation-quality end-to-end, and eval cases 85–95.
**No score, pass/fail or "certified" claim is made for any of them.** v1.7.0's evidence is exactly what §2
lists: structural, offline, deterministic. The reason is a deliberate provider constraint — no personal
model provider is configured, and the only available provider is an institutional/government one that must
not bill a personal project, so the pilot stays unrun by choice, not by failure.

## 5. How to run the pilot when a personal provider exists

Prerequisite: a **personal** provider — a personal `ANTHROPIC_API_KEY`, or a personal GCP project for
Vertex (never the institutional one). Then, from a clean environment that neutralizes inherited
corporate/government credentials:

```bash
# NOTE (post-release correction): the 1.6.0-worktree arm below is NOT executable — cases 96–115 exist only in the
# 1.7 tree and --eval-dir cannot point outside the plugin. Use this tree's plugin (default PLUGIN) and record the
# SHA; see docs/review/v1.7.0-pilot-plan.md "Arm B". CASE='96-*' runs one case first.
env -i HOME="$HOME" USER="$USER" PATH="$HOME/.local/bin:$(dirname "$(command -v node)"):/usr/bin:/bin" \
  EVAL_PROVIDER=anthropic ANTHROPIC_API_KEY="<personal-key>" \   # or: EVAL_PROVIDER=claude-ai EVAL_EXPECTED_ORG_ID=<orgId> (5B)
  CLAUDE_CONFIG_DIR="$HOME/.claude" \
  ALLOW_SCAFFOLD=1 BUDGET=1 MAX_TOTAL_USD=5 MODEL=haiku JUDGE_MODEL=haiku RUNS=1 \
  bash verification/evals/run-evals.sh pilot
node verification/evals/summarize.mjs plugins/frontend-architect/evals/results/pilot-<stamp>
```
The harness refuses to run without an explicit `EVAL_PROVIDER`, refuses the institutional project, and
refuses a `BUDGET` above `MAX_TOTAL_USD` (`--max-cost-usd` turned out to be the ceiling for the whole invocation, not per run — corrected 2026-11-13). Since 5B it also accepts the CLI's own claude.ai
subscription login (`claude-ai`, first-party, org pinned by `EVAL_EXPECTED_ORG_ID`; `USER` must be carried under
`env -i` for the Keychain login to resolve); under a subscription the ceiling bounds the *estimated* cost. `env -i` clears the inherited
`CLAUDE_CODE_USE_VERTEX=1` and the government ADC. Recommended first step: one case
(`--case 96-*`) to measure real cost before the eight. Reference cost: the 8×2 Haiku smoke was 0.47 USD.
The `--ablation with-without` gives the no-FA and FA arms at the tree you run from. One run per arm is **exploratory, not statistical** — a superiority claim needs
several runs with variance.

## 6. Concrete criteria to decide publishing v1.7.0

v1.7.0 can be published on either of two honest framings — pick one deliberately:

**Path A — publish as an evaluation-infrastructure + measurement-fix release (no behavioural claim).**
Publish when:
1. The integral gate is green on the exact tree to publish (re-run it immediately before).
2. `plugin-check` 0 warnings; `claude plugin validate` passes.
3. Manifests bumped to 1.7.0 coherently (plugin.json, marketplace.json, TOOL_VERSION) and the
   CHANGELOG 1.7.0 entry states plainly: new evaluation infrastructure + the browser-audit `toLoad` fix;
   **no new audit capability; behavioural evals NOT_RUN.**
4. A privacy/credential sweep of the 1.7 range is clean (no keys, no personal emails, no government/
   institutional project ids or accounts in committed files).
5. The RC is independently re-reviewed with fresh context, as 1.6.0 was.
6. The release notes do **not** claim the skill is measured-better than 1.6.0.

**Path B — hold the release until there is behavioural evidence.**
Do not publish 1.7.0 until the pilot has run under a personal provider and at least the exploratory
behavioural data exists (acceptance criteria in `v1.7.0-pilot-plan.md`), so the release can say something
true about behaviour, not only about structure.

Recommendation: **Path A is legitimate now** — the infrastructure and the `toLoad` fix are real, verified
value, and the version bump honestly describes them. Path B is stronger but gated on a personal provider.
Either way, the one thing the release must never do is present v1.7.0 as behaviourally certified.
