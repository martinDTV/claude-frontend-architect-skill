# v1.6.0 behavioural baseline — procedure (1.7 increment 1, prepared, NOT executed)

This is the reproducible procedure to capture a behavioural baseline of Frontend Architect at the
published v1.6.0 (`918306656ac294d83d5ea8680d7b4ef73c3e223f`), so later versions can be compared
against it. **Nothing here has been run.** Running it needs a model (an agent run), which is gated on
explicit authorization and a cost ceiling. This increment produced only the structural baseline and
this procedure.

## Three things that must never be conflated

1. **Structural baseline — available now, no model.** `plugin-check.mjs` (95 cases well-formed) and
   `eval-inventory.mjs` (the classification snapshot in `docs/eval-inventory.md`). This exists today
   and is what increment 1 delivers. It says what the suite *is*, not how the agent *behaves*.
2. **Behavioural baseline — requires running the agent.** The agent actually answers each prompt at the
   v1.6.0 plugin; the transcript is recorded; the deterministic (E0B) graders are computed from it.
   This is **NOT_RUN** until authorized. It is the only thing that measures behaviour.
3. **`--regrade` of existing transcripts — NOT a new behavioural run.** Re-computing graders over a
   previously recorded transcript. Useful to re-score an old run with a new grater; it must always be
   labelled as a regrade of run `<id>` dated `<when>`, never presented as fresh behaviour.

## What a baseline record must preserve (per run, per case, per arm)

- Plugin SHA (`918306656…`) and metadata version (1.6.0).
- Model id and configuration of the agent under test; judge model id (for any E1 grade).
- The exact prompt (`prompt.md` / `case.yaml` execution.prompt), verbatim.
- Fixtures / scaffold used and their SHA.
- Run parameters: `--runs`, arm (`with` / `without` in the ablation), `--max-turns`, `--allow-tools`,
  `--permission-mode`, `--max-cost-usd`.
- The full transcript (stream-json), stored.
- The graders applied and their type (E0B deterministic vs E1 judge).
- Results per grader and the composed case verdict (PASS/FAIL/NOT_RUN/INSUFFICIENT_EVIDENCE/
  INVALID_CONFIGURATION/HUMAN_REVIEW_REQUIRED).
- Date and environment (machine, OS, node, CLI version).

## Procedure (when authorized)

Reuse the existing infrastructure — do not write another runner.

1. **Pin the plugin at v1.6.0.** A clean checkout at `918306656…` (a worktree), so the baseline is of
   the published artefact, not the working tree.
2. **E0B-first, free of the judge.** Run the agent with the cheapest adequate model (Haiku) for the
   subset whose graders are deterministic (every case carries an E0B component — see the inventory),
   under a hard `--max-cost-usd`. Record transcripts. Compute the E0B graders with
   `transcript-assert.mjs`. This gives a behavioural baseline that needs no judge.
   - Command shape (do not run without authorization and a ceiling):
     `verification/evals/run-evals.sh` with `MODEL=claude-haiku-5-5 RUNS=1 --max-cost-usd <ceiling>`,
     then `node verification/evals/summarize.mjs <results-dir>`.
3. **E1 only when authorized with budget.** For the quality (judge) grades, add `--judge-model haiku`
   first (cheap), escalate to the stronger model only for a final RC with an explicit, larger ceiling.
   Keep every E1 result labelled with its judge and NOT_RUN until actually run.
4. **Store under `plugins/frontend-architect/evals/results/<mode>-<timestamp>/`** (gitignored) and
   summarize; the committed baseline is the summary table plus the record fields above, not the raw
   transcripts.
5. **Re-grade, don't re-run, for grader changes.** When a grater is refined, `--regrade` the stored
   transcripts and keep both verdicts side by side.

## Cost posture

- E0A (structural, `plugin-check` + inventory): **free, done.**
- E0B behavioural with Haiku: a small per-run token cost (the 1.6 audit case ran ~0.28 USD/run at 10
  turns; most cases are 10 turns). A bounded subset under `--max-cost-usd` is the first pilot.
- E1 judge: adds the judge model's cost; measured range for the ui-briefs suite was 10–25 USD (Sonnet)
  / 2–5 USD (Haiku) for 24 runs.
- Hard rule: **no run without `--max-cost-usd`.** `run-evals.sh` already enforces this.
