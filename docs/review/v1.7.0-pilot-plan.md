## Reproducible arms (version isolation)

`claude plugin eval` runs the `--ablation with-without` by default when the plugin resolves, giving two
arms per case:
- **Arm A — no Frontend Architect:** the model answers with the plugin absent. The eval sandbox gives it
  no plugin instructions and no plugin scripts, so it cannot accidentally reach them.
- **Arm B — Frontend Architect at the published tree (1.7.0).** The plan first said "a worktree of 1.6.0", but
  that is not executable: cases 96–115 exist only in the 1.7 tree and `--eval-dir` is a directory *below* the
  plugin, not another tree. The skill content of 1.7.0 is identical to 1.6.0 except the `browser-audit` toLoad
  measurement fix (no rule, reference or prompt changed), so arm B measures the same skill behaviour. Record the
  exact SHA of the tree used (`git rev-parse HEAD`) with every run.
- **Later versions:** the same two arms at each later tree; comparisons between trees are between runs, not arms.

Record per run: model id, provider, CLI version, plugin SHA, prompt, fixture, allowed tools, permissions,
params, budget, transcript, graders, state. `summarize.mjs` emits per-case scores per arm and the
activation indicator. The with-only graders (ran-a-script, skill-activation) count only in the plugin arm.

## Safety properties (verified offline)

- **Scaffolds run in the eval sandbox**, not the repo; each case's `scaffold.sh` builds a throwaway app.
  The `ALLOW_SCAFFOLD=1` gate is enforced — the pilot refuses to run scaffolds without explicit opt-in.
- **`--no-publish` always set** — the HTML report stays local, never uploaded to claude.ai.
- **`--max-cost-usd` always set, `-j 1`** — a budget overrun is bounded to a single run.
- **No corporate/government credential.** `run-evals.sh` would use Vertex ADC if `CLAUDE_CODE_USE_VERTEX=1`;
  on this machine that ADC is the corporate profile. The pilot MUST run with a **personal provider**
  and `CLAUDE_CODE_USE_VERTEX` unset, under a personal `CLAUDE_CONFIG_DIR`. The zsh `claude` function
  forces the corporate profile, so the pilot must invoke the real binary (`~/.local/bin/claude`) with the
  personal config explicitly.
- A provider or budget error must end the run in a **failure / NOT_RUN**, never a PASS; `--threshold 0`
  makes the exit report budget/structure, and graders only PASS on observed events, never on prose.

## Acceptance criteria (measurable; exploratory, not statistical)

For the pilot to be ACCEPTED as a first behavioural data point:
- **Real runs recorded:** 8 cases × 2 arms produced transcripts; none errored into a fake PASS.
- **Tool use observed (arm B):** on the six positives, the correct auditor's invocation appears in the
  transcript (the `ran-a-script` grader), not just claimed in prose.
- **Diagnosis vs ground truth:** for each positive, the planted defect is cited at the right path:line
  (the `criteria` grader), with FP/FN noted per case.
- **Abstention (both arms):** 113/114 are answered without an auditor run and still complete the task.
- **Cost recorded** and under the ceiling; **arm differences** reported per case.
REJECT if runs error silently, if the plugin arm does not actually run tools, or if diagnoses are invented.

**Honesty bound:** one run per case per arm is **exploratory**. It cannot support a general claim that
Frontend Architect makes Claude Code better — frontend/audit behaviour is variable. A statistical claim
needs several runs per arm with the variance reported. The pilot answers "does the machinery work
end-to-end and what does a first look show", not "is 1.7 better".

## Exact command (to run ONLY after you authorize provider + budget)

From a personal shell with a personal provider configured (no corporate profile, no corporate Vertex):

```bash
# Arm comparison is built in (--ablation with-without). Point PLUGIN at the 1.6.0 snapshot.
# PLUGIN defaults to this tree's plugin; record `git rev-parse HEAD` with the run (see Arm B above)
# clean env (no inherited provider): USER is needed for the Keychain-stored claude.ai login to resolve
env -i HOME="$HOME" USER="$USER" PATH="$HOME/.local/bin:$(dirname "$(command -v node)"):/usr/bin:/bin" \
  EVAL_PROVIDER=claude-ai EVAL_EXPECTED_ORG_ID="$(claude auth status | node -pe 'JSON.parse(require("fs").readFileSync(0)).orgId')" \
  ALLOW_SCAFFOLD=1 BUDGET=1 MAX_TOTAL_USD=5 MODEL=haiku JUDGE_MODEL=haiku RUNS=1 \
  CASE='96-*' \                                   # first: ONE case, to measure real consumption; drop CASE for all eight
  bash verification/evals/run-evals.sh pilot
# (or EVAL_PROVIDER=anthropic ANTHROPIC_API_KEY=<personal-key> for a pay-as-you-go key)
# then: node verification/evals/summarize.mjs plugins/frontend-architect/evals/results/pilot-<stamp>
```
(`run-evals.sh pilot` assembles: `claude plugin eval <PLUGIN> --runs 1 -j 1 --no-publish --trust-plugin
--model haiku --judge-model haiku --max-cost-usd 1 --threshold 0 --tag suite:pilot --scaffold
--allow-tools Bash --disallow-tools Write Edit WebFetch WebSearch` (full Bash since 2026-11-13: see the harness comment and CHANGELOG — narrower grants denied the script call itself), with the result/report under
`evals/results/`, gitignored. Recommended first step: `--case 96-*` alone, to measure real consumption.)
