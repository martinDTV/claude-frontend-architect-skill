# Frontend Architect v1.6.0 — Independent fresh-context audit

A reviewer with **fresh context** (a general-purpose agent of the same model family, started without
this session's implementation history) audited the 1.6.0 performance line (`cef5ab9..HEAD`) with the
explicit mandate to **refute** the claim that the tools are correct and safe, not to confirm it. It
received only the repository, the functional scope, the public contracts, the acceptance criteria and
the reproduction instructions — not the author's GO dictum, implementation assumptions or decision
justifications. It worked read-only and made no edits, commits or stages.

This document records the audit as delivered, the author's independent re-verification of each
finding, and what was done about them. It does not claim independence over any area the reviewer did
not examine.

## Findings — both CONFIRMED by independent re-verification, both Minor

### [Minor] H1 — the compare note could deny the per-run range it carried

`perf-budget.mjs` compare verdict. When both result sets carried a per-run range and the ranges were
**separated** (did not overlap) but the p75 point moved less than the ±2 % floor, the verdict fell
into the `tiny` branch and emitted the note "within the +/-2% noise floor … (no per-run range to test
overlap)" — contradicting the `range` field of the same record, which showed the ranges existed. The
verdict (`inconclusive`) was already conservative and correct; only the note text was wrong. This
matters because honest evidence-labelling is this tool's core claim.

- **Reproduction:** before p75 2200 (range 1800..2400) vs after p75 2170 (range 1500..1799) → delta
  −1.36 % (< 2 %), ranges do not overlap → `verdict: inconclusive`, `range: {before:[1800,2400],
  after:[1500,1799]}`, note previously claimed "no per-run range".
- **Fix:** the `tiny` branch now names the ranges when they exist ("the per-run ranges separate …
  but the point moved less than the floor") and only says "no per-run range" when there genuinely is
  none. Locked by fixtures `L-before.json` + `M-tiny-separated.json` and the test "M: a sub-2% move
  with separated ranges is inconclusive, and the note does not deny the ranges it carries".

### [Minor] H2 — two new tools omitted the documented `analysis` contract field

The documented report contract is `{tool, version, root, framework, summary, findings, notes, data,
analysis}`. `createReport` (`lib/report.mjs`) does not include `analysis` in the base object; each
tool adds it. `perf-audit` did (a string); `route-attribution` and `perf-budget` did not, so their
JSON had no `analysis` key. The frozen contract test (`semantic-engine.test.mjs`) asserts `analysis`
but iterates only the six graph tools, so it did not catch the two new omissions. Low impact (no
in-repo consumer dereferences `.analysis` blindly), but it is a documented-contract violation and an
inconsistency.

- **Reproduction:** run each with `--json`; `"analysis" in report` was false for `perf-budget` and
  `route-attribution`, true for `perf-audit` and every frozen graph tool.
- **Fix:** `route-attribution` and `perf-budget` (both compare and evaluate modes) now set a
  descriptive `report.analysis` string, matching `perf-audit`'s convention. Locked by the tests "the
  report carries the full contract shape including analysis" in both `perf-budget.test.mjs` and
  `route-attribution.test.mjs`.

## What the reviewer tried to break and could not (verified correct)

- Absence never masquerades as PASS: a missing metric → `null` → UNAVAILABLE; a genuine 0 (CLS 0,
  server-only route) → available PASS. CLS 0 → 0.3 compares as **regressed** despite `percent:null`
  (driven by range separation and absolute delta; the `tiny` guard requires `before.value !== 0`).
- Interaction decomposition (inputDelay / processing / presentation) sums to `duration`;
  interactionId-0 events are excluded from grouping; the representative is the slowest in the group;
  the Playwright wall-clock is kept as `wallMsProxy` labelled "PROXY, not INP" and never fed into the
  latency metric.
- Hydration: an exact time is claimed only with an app `performance.mark`; otherwise
  `available:false` and Navigation-Timing values are labelled proxies.
- Shared-counted-once holds (a shared chunk is counted once per route, the two routes are not summed);
  built bytes are never equated with transferred bytes — every report repeats the "built ≠
  route-associated ≠ transferred ≠ used" caveat.
- Render strategy (SSG/ISR/dynamic) reads correctly from the manifests; a missing manifest →
  `unavailable` with a reason, no crash and no guess.
- The five budget states and their boundaries fire correctly; minSamples exempts build facts; the
  default `onMissing` is UNAVAILABLE with exit 0, only the opt-in `onMissing:fail` is FAIL with exit
  1; compare refuses incompatible unit/profile pairs.
- Auditor safety: each Playwright context installs its own `route('**/*')` guard enforcing the host
  allowlist (localhost/127.0.0.1/::1 plus explicit `--allow-host`); non-allowlisted requests are
  aborted and logged; no auth is ever attempted; forms require `--allow-submit` and password-field
  forms are never submitted; `safeDir` resolves symlinks and constrains writes to cwd/temp.

and used read-only tools. No files were modified by the reviewer.

## Overall read

No Blocker or Important defects. Two Minor, both now fixed with tests, plus the contract test the
reviewer recommended (covering the new tools) now in place. The honesty invariants the release is
built around — no false PASS from absence, no equating build/transferred bytes, no wall-clock-as-INP,
no exact hydration time without a marker, no cross-profile/unit comparison, shared-counted-once — all
held under adversarial inputs.
