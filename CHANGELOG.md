# Changelog

All notable changes follow [Keep a Changelog](https://keepachangelog.com/) and [Semantic Versioning](https://semver.org/).

## [1.4.0] - 2026-10-29

### Fixed
- **`routes-audit` misread `definePageMeta`.** The middleware list is now read from the AST (`summary.metaParser: ast`): arrays with `//` or `/* */` comments, identifiers and inline functions (`middlewareUnknown`), `layout`, `redirect` and `auth` are parsed as code, so `['auth', /* step-up */ 'step-up']` no longer produces a false `unknown-middleware`. The lexical fallback strips comments but keeps strings (previously it blanked them, losing every name). Pages whose script only redirects (`navigateTo`, `router.replace`/`push` with an empty template, or `definePageMeta({ redirect })`) are `status: redirect` with `redirectTo` and `redirectGuarded` and reported as `redirect-page` (info; medium when the target page is unguarded) instead of `page-without-guard`. Fixture pages for all three cases, positive controls in the tests (a wrong name is still confirmed, a redirect to an unguarded page is medium, a handler that navigates is still unguarded).
- **`--typecheck` counted agreements as disagreements** when the syntactic origin was a declaration file the checker also resolved (7 false disagreements on a real Nuxt project); `declaration-file` origins at the same file now agree.
- JSX attributes with numeric literals (`tabIndex={2}`) are read as values; Vue template elements are recorded in document order (the walker visited siblings in reverse, which hid heading-order facts).

### Added
- **Static UI audit** (`scripts/ui-audit.mjs`, `--rules a11y,forms`): accessibility and form-quality patterns judged on the compiler-sfc template AST and the TypeScript JSX AST (attributes, bindings, events, parents, children). Every finding carries `verification`: `static` (the markup proves it; confirmed), `review` (heuristic), `browser` (info). Controls inside a component that declares a label-like prop are counted as `encapsulatedByComponent` and not reported; spreads are `unverifiable`. Seventeen a11y rules (`img-missing-alt`, `form-control-without-label`, `button-without-accessible-name`, `link-without-href`, `click-handler-on-non-interactive`, `nested-interactive`, `aria-hidden-on-focusable`, `invalid-role`, `unknown-aria-attribute`, `positive-tabindex`, `heading-level-skipped`, `iframe-without-title`, `image-input-without-alt`, `dialog-without-name`, `table-without-headers`, `mouse-only-handler`, `img-alt-dynamic`) and three form rules (`form-error-not-associated`, `form-without-pending-state`, `required-visual-only`). Under the lexical engine findings that need the element tree degrade to `review`, JSX is not scanned and the note says so. Calibrated by reading every static finding on an 80k-line Nuxt application: names come from any descendant text, `@click.stop` and propagation-only handlers are not interactions, a click that only focuses an inner control is `review`, a control hidden by a display:none class is a `browser` check and the HTML `hidden` attribute skips it (static findings there went from 52, 37 of them false, to 15, all confirmed by reading). Fixture `ui-app` with a truth written before the rules ran and extended with those negative controls: precision and recall 100% (semantic); the lexical degradation is measured in `docs/benchmarks.md`. Not WCAG conformance, and the tool says so.
- **Browser mode** (`scripts/browser-audit.mjs`, opt-in): rendered-page checks with Playwright and axe-core supplied by the user (`--playwright <dir>`; the plugin installs and bundles nothing). Enforced safety: refuses to run without the tooling directory; only `localhost`/`127.0.0.1` unless `--allow-host`, every other request blocked and listed; no authentication (`auth-required`); `--interact` never clicks destructive buttons; `--allow-submit` required for the forms check; `--max-time`/`--max-pages` budgets; `--out` must be under the working directory or the OS temp dir; `--mask` selectors blacked out in screenshots and dropped from evidence; baselines written only with `--write-baseline`/`--approve`. Checks: `axe` (critical/serious confirmed, the rest `axe-needs-review`), `keyboard` (`keyboard-unreachable`, `hover-only-disclosure`), `dialogs` (`custom-modal-without-dialog-role`, `dialog-focus-not-moved`, `dialog-escape-does-not-close`, `dialog-focus-not-restored`), `responsive` per viewport and text scale (`horizontal-overflow` with culprits outside intentional scrollers, `control-cut-off`, `control-covered`, `dialog-exceeds-viewport`, `navigation-unreachable`), `hydration` (`hydration-mismatch`, `client-only-rendered-content`), `forms` (`form-no-validation-feedback`, `form-error-not-associated`, `form-focus-not-moved-to-error`, `form-double-submit` proven by two requests, `form-no-pending-state`, `form-no-success-feedback`), `visual` (baselines per page and viewport with browser, platform, versions and viewport metadata; `visual-baseline-missing`, `visual-baseline-written`, `visual-environment-mismatch` with no verdict, `visual-regression`, `visual-difference-accepted`). Zero-dependency PNG decode and diff (`lib/png.mjs`). Local HTML fixture with a counting server (`verification/browser/fixture`) and a truth of must-have / must-not-have findings per page; `verification/browser/browser-audit.test.mjs` (refusals, fixture truth, visual lifecycle) runs in CI with pinned Playwright 1.64.1 and axe-core 4.14.0 and Chromium; `FA_REQUIRE_BROWSER=1` turns a missing browser into a failure.
- **SSR and hydration rules** in `state-audit`: `browser-api-in-setup` (confirmed/high at the top level of `<script setup>`, in a Nuxt `setup()` or in module scope with SSR on; heuristic/medium in a React render body; low with `ssr: false`) and `nondeterministic-render` (heuristic), from the AST context of each identifier (enclosing calls, function, guards). Silent inside lifecycle hooks and handlers, under client guards (`import.meta.client`, `process.client`, `typeof window !== 'undefined'`, `isClient`, `onNuxtReady`) and in `.client.` files; `'use client'` is not a guard. Fixture `ssr-app` with truth and negative controls, Next.js fixtures `WindowInRender.tsx`/`WindowInEffect.tsx`.
- **Type-checker budgets and accounting** (`domain-deps --typecheck`): `--typecheck-max-source-mb` (20) and `--typecheck-max-heap-mb` (1024) next to `--typecheck-max-files` (2500); `analysis.typechecker` records root files, source files loaded, wall ms, CPU ms, heap MB and RSS MB; over budget or on failure the syntactic origins stand with a reason. Measured read-only on two real Nuxt projects (`docs/benchmarks.md`).
- **Frozen 1.3 behaviour**: 61 finding baselines (`verification/tools/baselines/1.3.0/`, fingerprint `id|file|line|level|severity` per tool, fixture and engine, plus summary keys) and 61 JSON shapes (`contracts/1.3.0/`); `baseline-findings.test.mjs` fails when a 1.3 finding disappears or changes grade without an entry in `baselines/migrations.json` (empty for 1.4.0: nothing was removed or re-graded).

- Skills and agent: `references/ui-verification.md` (levels, authorisation checklist, forms matrix, responsive and visual rules, SSR, human criteria, report shape); two sentences in `frontend-architect` `SKILL.md` and one in `creative-frontend`; the `frontend-reviewer` agent runs `ui-audit`, never runs browser mode on its own, and groups findings into architecture failures, accessibility failures, confirmed visual or behavioural defects, heuristics and design recommendations.

- Verification: `ui-audit`, `ssr-rules`, `baseline-findings` suites and extended `routes-audit`, `read-only` (browser exception bounded; `ui-audit` in the byte-identical check) suites: 82 → 99 static tests plus 3 browser tests; `benchmark.mjs` adds rule-level precision rows (ui-app, ssr-app, both engines, time and peak RSS); `run-all.sh` and CI run the browser suite.
- Evals 67–77 (static a11y levels, encapsulated-component false positive, forms audit, browser-mode authorisation and production refusal, intentional scroller, visual baseline governance, SSR window in setup, after-mount false positive, middleware arrays with comments, type-checker budgets, a third joint-activation probe). ### Changed
- `TOOL_VERSION` 1.4.0; manifests 1.4.0. JSON reports are additive over 1.3.0 (compat suite against the 1.2.0 and 1.3.0 shapes). `routes-audit` adds `summary.redirects`, `summary.metaParser` and page fields `status: redirect`, `redirectTo`, `redirectGuarded`; previous page statuses are unchanged.
- The static tools stay read-only and spawn nothing; `browser-audit` is the one documented exception and the read-only suite bounds it (its writes go under `--out`/`--baseline-dir`; no static tool imports it).
- Lexical fallback and every 1.1–1.3 flag, exit code and finding id unchanged.
- **Neutral vocabulary.** The synthetic fixtures (`nuxt-app`, `vue-templates`), the audit eval scaffold and `assets/frontend-audit.example.json` use sector-neutral English names (sales, projects, documents, people, catalog) instead of names borrowed from a calibration project; the plugin never depended on them, and the 1.2.0/1.3.0 contract shapes and the 1.3.0 finding baselines were regenerated by running the released 1.2.0 and 1.3.0 scripts on the renamed fixtures (same behaviour, new names).
- Forms check refined after running it on the Next.js reference example: a double submission is confirmed only when the second request leaves before the first response arrives (two sequential submissions after a fast response are the same id as heuristic); the pending state is sampled every 10 ms while the first request is in flight and a response faster than the first sample is recorded as not observable instead of reported; `role="alert"` changes count as feedback; an alert referenced by any control's `aria-describedby`/`aria-errormessage` is associated; native validation is detected through `validity`, not through the absence of `aria-invalid`; focus to the first invalid field is required only for field-level errors. The documented `RenameUserForm` (`references/nextjs.md`) now marks the field `aria-invalid`, moves focus back to it, locks the form with `aria-busy` and confirms success in a `role="status"` region; `verification/next/check-browser.mjs` serves the built reference app and asserts the example passes the forms check (harness and CI).
- Browser mode hardening after review: `--baseline-dir` is validated like `--out` (working directory or OS temp dir, symlinks resolved, whole path segments) and created only when a baseline is written; forms with a password field are never submitted, even under `--allow-submit` (`form-skipped-credentials`); text of masked elements is replaced by `[masked]` in every message, evidence string, page title and console line.

## [1.3.0] - 2026-10-29

### Fixed
- **Scripts reached through a symbolic link did nothing and exited 0.** The main-module guard compared `import.meta.url` with `process.argv[1]` as strings, so `/tmp` on macOS (a link to `/private/tmp`), linked plugin installs, relative invocations from another directory and paths with spaces skipped `run()`. All seven tools now use `isMainModule()` (real-path comparison). Covered by tests through a symlinked directory with a space in its name, and by a harness step and a CI step that fail when a linked tool prints nothing.
- **`bundle-budget` summed assets of several builds.** Totals now cover only the assets the current build manifest references (`assetScope: manifest`); leftovers of earlier builds are listed as `stale-build-artifacts` with their own size (`staleFiles`, `staleJsGzipKb`) and never added. Nuxt build ids (`builds/latest.json`, `builds/meta/*`), Next.js `BUILD_ID` directories, Turbopack client reference manifests and Vite's `.vite/manifest.json` are read. When a bundler's inventory is not complete (Next.js without `app-build-manifest.json`), unreferenced files stay measured as `unreferenced`, never guessed stale. `sharedBy`/`sharedChunks` come from the Nuxt import graph. Without any manifest the scope is `directory` and the report says so.
- **Vue special elements reported as unknown components.** `<component>`, `<transition>`, `<keep-alive>`, `<Teleport>`, `<slot>` in any casing are classified as built-ins; every template component use is now classified as `local` (imported or declared), `builtin`, `nuxt-metadata` (verified), `catalog` (inferred), `package`, `dynamic` (`<component :is="expr">`, listed separately with the expression) or `unknown`; `is="X"` and string literals inside `:is` resolve to components; lowercase words in `:is` never become component names.
- `server-env-in-client` no longer fires when a client component imports a `'use server'` module that reads private environment (Server Actions run on the server). Found by auditing the Next.js reference project.
- `contracts-check` treats a subpath published through `package.json` `exports` as a public entry, not as an internal import.

### Added
- **Exclusions** (`exclude` in `.frontend-audit.json`, `--exclude a/**,b` on every tool): validated patterns (absolute paths, `..`, backslashes, empty or catch-all patterns stop the tool with exit 2), bare directories match their subtree, and every report carries an `excluded` block plus a note with the file count, patterns that matched nothing and the number of edges dropped because they pointed at excluded files. Excluded code is not audited and the report says so.
- **Symbol origins through barrels** (semantic engine): for every named import, the file that declares the name after following `export { a as b } from`, `export *` (ESM order, cycle and depth guards), re-exports of imported names and `.vue` defaults; `declared`, `declaration-file`, `not-found`, `external`, `cycle` statuses with the number of barrel hops. Exposed per edge as `origins`, summarised in `symbolResolution`, and usable through `domain-deps --follow-reexports` (adds importer → declaring-file edges, `via: reexport`, so matrices and cycles see the owner, not only the barrel). `contracts-check` adds `reexport-crosses-module` (a barrel publishing names declared in another module or outside the modules tree, one finding per owner) and `exportOrigins` per module.
- **Optional TypeChecker verification** (`domain-deps --typecheck`, `--typecheck-max-files`, default 2500): a TypeScript Program is created lazily for the TypeScript/JavaScript files, the compiler's alias resolution confirms or corrects each syntactic origin (`verifiedBy: checker`, `disagreement`, `resolvedByChecker`), `.vue` importers are reported as outside the Program, and the budget or any failure leaves the syntactic results in place with a reason. `analysis.typechecker` records files, duration and heap.
- **Monorepos**: pnpm (`pnpm-workspace.yaml`), npm and yarn (`workspaces`) workspaces are detected; packages inside the audited root resolve by name through `package.json` `exports` (conditions, subpath maps and patterns) or `main`/`module`/`types` (`resolution: workspace`); the nearest `package.json` above an importer supplies its declared dependencies; `tsconfig` project references and per-package `tsconfig.json` give each directory its own compiler options; a workspace root without a framework of its own is analysed as `framework: workspace`; an app inside a bigger workspace sees its siblings as `workspace` package imports, named but never followed. `contracts-check` takes a package's entry from `package.json` and adds `package-subpath-not-exported` (confirmed) for deep imports a package does not publish.
- **Dependency policy** (`dependencies.allowed`, `dependencies.exceptions` in the config): every business pair becomes allowed, excepted or forbidden; `forbidden-dependency` separates runtime from type-only file pairs (type-only coupling is low severity, never hidden), `architecture-exception` keeps tolerated pairs visible with reason, since/until and current counts, and a cycle allowed in both directions is `allowed-cycle` (info) instead of a violation; a cycle with one excepted direction stays a `domain-cycle` with the exception noted.
- **Next.js**: `client-only-in-server` (a Server Component or route handler reaching an `import 'client-only'` module through modules that are not client boundaries, confirmed when verified); the Next.js reference project built by the harness is now audited after `next build` (`verification/next/check-audit.mjs`): semantic engine with the project's own TypeScript, no boundary findings, Server Function and Route Handler inventoried, `.next` measured through its manifests.
- **Vue**: template literal expressions (`${…}` in scripts and bound attributes) and `is` targets are part of the template analysis; a fixture with a hand-written truth (`vue-templates`) covers built-ins, kebab-case and `Lazy` tags, dynamic components, JSDoc/HTML comments that mention components, and auto-imports used only inside template literals.
- `leak-patterns`: `BroadcastChannel`/`MessageChannel`, `Worker`/`SharedWorker`, `requestIdleCallback` and `getUserMedia`/`getDisplayMedia` resources, with positive and negative fixtures.
- Verification: `defects-1.3`, `compat` (every key path of the 1.2.0 JSON reports, snapshotted under `verification/tools/contracts/1.2.0/`, must survive with its type), `symbols`, `monorepo`, `policy`, `next-boundaries`, `typecheck` and `read-only` (static scan for process execution, network and writes; byte-identical project after running every tool) suites: 42 → 82 tests. Fixtures `vue-templates` and `monorepo` with ground truths written before the engines ran, `ts-paths/expected-symbols.json`. `benchmark.mjs` scores symbols, accepts `--baseline <scripts-dir>` to compare another version on the same fixtures, warms up the compilers before timing, and lists fallbacks.
- Evals 55–66 (barrels, monorepos, Vue built-ins, template literals, comments, client/server boundaries, a say-no case about flagging `'use client'` and `useState`, policy and allowed cycles, engine choice, untrusted repositories, exclusions and stale builds, joint activation of both skills). Structure validated, not run.

### Changed
- `TOOL_VERSION` 1.3.0; manifests 1.3.0. JSON reports are additive over 1.2.0 (verified by the compat suite); the one semantic change is `bundle-budget.totalJsGzipKb`, which excludes provably stale assets (their size is reported separately).
- Lexical fallback and every 1.1/1.2 flag, exit code and finding id unchanged.

## [1.2.0] - 2026-10-28

### Added
- **Semantic Architecture Engine** for the six graph-based audit scripts (`domain-deps`, `contracts-check`, `state-audit`, `routes-audit`, `leak-patterns`, `component-complexity`): TypeScript, TSX and JavaScript parsed into syntax trees with the audited project's own `typescript`; `.vue` files parsed with its `vue/compiler-sfc` (script bindings and template AST); module specifiers resolved with the project's `tsconfig` through `ts.resolveModuleName` (Nuxt 4: the generated `.nuxt/tsconfig.app.json` and `tsconfig.server.json`). Lives in `scripts/lib/semantic/` (`host`, `tsconfig`, `ts-module`, `vue-sfc`, `resolver`, `graph-semantic`); no dependency is added to the plugin and nothing of the project is executed beyond loading those two libraries.
- Flags on the six tools: `--engine auto|semantic|lexical` (default `auto`: semantic when a usable `typescript` is found, otherwise lexical with the reason stated; `semantic` exits 2 instead of falling back), `--typescript <dir>`, `--vue-compiler <dir>`, `--format text|json|markdown`. Every report opens with an `Analysis` line (JSON: top-level `analysis`) naming the engine, compiler versions and paths, tsconfig files, resolution counts and per-file fallbacks.
- Edges now carry `kind` (`runtime` | `type`), `resolution` (`typescript`, `tsconfig-paths`, `relative`, `nuxt-metadata`, `lexical-catalog`, `lexical-alias`), `importKind`, `specifier` and `col`. `domain-deps` lists *Unresolved imports* (non-literal dynamic imports, missing files, undeclared specifiers) and *packages imported*; new findings `server-only-in-client` (Next.js: a `'use client'` module reaching an `import 'server-only'` module through runtime imports; confirmed when the chain is verified), `server-env-in-client` (heuristic) and `unresolved-import` (info).
- `verification/tools/fixtures/ts-paths`: a fixture with a hand-written ground truth (`expected-edges.json`, 19 edges) covering `paths` aliases, barrels, type-only imports, a runtime cycle, dynamic imports and SFCs; `verification/tools/semantic-engine.test.mjs` (11 tests; suite 31 → 42); `verification/tools/benchmark.mjs` (precision, recall, F1, unknowns, time and heap per engine on the fixtures; `--real <root>` diff mode for a project) wired into `run-all.sh` and CI.
- Docs: `docs/semantic-engine.md` (design, resolution labels, framework adapters, trust boundary, limits, how to verify a finding, JSON additions), `docs/benchmarks.md` (fixture and real-project measurements), an "Analysis engine" section in `scripts/README.md`, a 1.2.0 addendum in `docs/validation-report.md`.
- Six eval cases (49–54): hidden coupling through aliases, Nuxt auto-import dependency mapping, server-only code reaching the client, a Vue cleanup false positive to refuse, SSR state with late responses per tenant, a public-contract breaking change. Structure validated; not run (no paid run was authorized for this pass). `docs/evals.md` records the case-48 activation analysis and a proposed, unexecuted A/B for 1.3.

### Changed
- `domain-deps`: type-only edges lower the severity of boundary findings (`low` for shared/shell, `medium` for internal imports) and never form cycles; `domain-cycle` is `confirmed` when both directions are verified runtime imports under the semantic engine; `feature-internal-import` level follows the edge confidence and shows the resolution; edge targets outside the scanned sources (declaration files) are classified by the same convention rules instead of `other`.
- `contracts-check`: `internal-import` is `confirmed` only on verified edges, `medium` when type-only, with the specifier and resolution as evidence.
- `routes-audit`: `'use client'` / `'use server'` read as directive prologues from the AST when available.
- `leak-patterns`: a cleanup hook counts when it is a real call (`onBeforeUnmount`, `onUnmounted`, `onScopeDispose`, `useEffect` returning a function, `.dispose()`), not a word in a comment; rows carry `cleanupSource`.
- `component-complexity`: `.vue` metrics from `compileScript` bindings and the template AST (`metricsSource: ast`), `.ts/.tsx` metrics from the TypeScript AST (`ast-script`); nested generics in state declarations no longer break the count; rows add `componentsUsed`, `lifecycleHooks`, `imports`.
- Lexical engine unchanged in behavior; its edges now also report `kind`, `importKind` and `resolution: lexical-alias | nuxt-metadata | lexical-catalog` so both engines share one contract. `TOOL_VERSION` 1.2.0. `SKILL.md` gains one sentence on the engine (+~60 tokens by the chars/4 estimate; the `claude plugin details` measurement was not repeated in this pass); the `frontend-reviewer` agent quotes the engine and the resolution of an edge when a finding depends on it.
- Manifests 1.2.0; descriptions mention that the scripts parse with the project's own TypeScript and `vue/compiler-sfc`.

### Fixed
- Auto-import edges created by a property name or object key that happened to match an auto-imported symbol (three such false positives on an 80k-line Nuxt app) no longer appear under the semantic engine, which counts value identifiers only.
- Template depth no longer inflated by `>` inside attribute expressions when the SFC compiler is available.
